# Support

Summary
Where to ask for help. Use GitHub Issues on the repository that owns the
component. This is not the security or Code of Conduct path.

## How to get help

Open an Issue on the owning repository:

```text
Kernel / driver → Carbon-XDNA
Runtime / execution / APIs → Diamond-accel0
Compilation / artifacts → Steel (when the public repository exists)
Monitoring / diagnostics → the relevant observability repository
```

Include hardware model, Fedora version, kernel version, component versions, and
repro steps when filing a bug. Use N/A when a field does not apply.

## What this is not

- Security vulnerabilities → [SECURITY.md](SECURITY.md) (private vulnerability
  reporting only).
- Sensitive Code of Conduct reports → private reporting on `.github` with
  `[Code of Conduct]` prefix; see SECURITY.md and CODE_OF_CONDUCT.md.
- General product redesign debates → see [GOVERNANCE.md](GOVERNANCE.md) and
  [PROJECT_SCOPE.md](PROJECT_SCOPE.md).

[profile/README.md](profile/README.md),
[profile/ARCHITECTURE.md](profile/ARCHITECTURE.md).
