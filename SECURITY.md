# Security Policy

Summary
How to report vulnerabilities and related private reports. Vulnerability intake
is GitHub private vulnerability reporting on the affected repository—not Issues
or Discussions.

## Reporting a vulnerability

Use GitHub private vulnerability reporting on the affected repository
(Security tab → Report a vulnerability).

Do not open a public Issue for vulnerabilities.
Do not post vulnerabilities in Discussions.
Do not share exploit proof-of-concept detail in public channels.

A durable project security email may come later. Until then, private
vulnerability reporting is the only supported vulnerability intake.

## Security process (Discussions)

When Discussions are enabled on this repository, non-sensitive security process
questions may use the Security category:

https://github.com/The-Iridium-Road/.github/discussions/categories/security

That category is not vulnerability intake. Until Discussions exist, do not use
public Issues for vulnerabilities—use private vulnerability reporting only.

## Code of Conduct (private reports)

Private vulnerability reporting on this `.github` repository is also used for
sensitive [Code of Conduct](CODE_OF_CONDUCT.md) reports. Prefix the title with
`[Code of Conduct]`. Do not use public Issues or the Security Discussions
category for sensitive conduct reports.

## Scope

In scope:

- Software under The Iridium Road (drivers, runtimes, compilers, tools, related
  project code).
- Sensitive Code of Conduct reports via private reporting on `.github` as above.

Out of scope for this process:

- Vendor firmware or hardware flaws not introduced by Iridium Road software
  (use the vendor’s channels when applicable).
- General support (Issues; see [SUPPORT.md](SUPPORT.md)).

## Expectations

Maintainers will acknowledge private reports when able and coordinate disclosure.
Give reasonable time before any public discussion of an unfixed issue.
